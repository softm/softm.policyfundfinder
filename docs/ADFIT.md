# 지원한눈 AdFit 광고 적용 계획과 운영 기준

기준일: **2026-10-22 (KST)**

- 운영 서비스: [지원한눈](https://policyfundfinder.designboard.net/)
- 소스: [softm/softm.policyfundfinder](https://github.com/softm/softm.policyfundfinder)
- 관리: [Kakao AdFit 광고관리](https://adfit.kakao.com/adManagement)
- 설정 원본: [`public/adfit-config.js`](../public/adfit-config.js)

## 1. 목표와 적용 범위

지원사업 검색·관심사업 확인 흐름에 하단 접기·펼치기 광고와 목록 중간 광고를 연결합니다. 돌봄한눈의 접기·펼치기, 상태 보관과 화면 공간 확보 방식을 참고하되, 광고단위는 지원한눈 Web 매체에 발급된 단위만 사용합니다.

현재 운영 구조인 정적 GitHub Pages에 적용합니다. 공고 수집 스케줄, 수집 데이터, 검색용 Web Worker, 브라우저의 사업 프로필·관심사업·준비 기록 저장 방식은 광고와 별도로 유지합니다.

## 2. 지면 계획

| 지면 | 크기 | 위치·수량 | 이용 중 동작 |
| --- | --- | --- | --- |
| 하단 모바일 | 320×50 | 하단 독립 공간에 1개 | 광고 밖 버튼으로 접기·펼치기, 모바일 메뉴와 간격 확보 |
| 하단 PC | 728×90 | 하단 독립 공간에 1개 | 실제 가용 폭이 충분할 때 선택, 모바일 단위와 동시에 요청하지 않음 |
| 목록 중간 | 320×100 | 공고 6개 뒤 1개, 최소 7개 공고 필요 | 공고 카드와 구분한 광고 행, 공고 건수·정렬·페이지 수에서 제외 |

하단은 두 규격 중 하나만 선택하므로 동시에 표시하는 지면은 최대 2개입니다. 이 수량과 공고 간격은 지원한눈의 화면 밀도를 고려한 설계값입니다. 광고를 CSS 배율로 줄이거나 일부를 잘라 맞추지 않으며, 필요한 폭을 확보하지 못하면 해당 지면을 요청하지 않습니다.

### 검색과 읽기 흐름

- 하단 광고의 높이를 레이아웃에 반영해 본문, 모바일 메뉴, 비교함을 가리지 않습니다.
- 접기·펼치기 버튼을 광고 `ins` 및 iframe 바깥에 두고 `aria-expanded`로 현재 상태를 알립니다.
- 사용자의 접힘 선택을 현재 브라우저 세션에 보관합니다. 입력이나 상세보기 때문에 일시 숨겨도 저장된 선택을 덮어쓰지 않습니다.
- 검색 입력, 상세 팝업, 첨부파일 뷰어를 사용하는 동안 하단 광고를 일시 숨깁니다.
- 자금 계산기·신청 준비 등 집중 작업 화면에는 하단 광고를 표시하지 않습니다.
- 빈 목록·로딩·오류 상태에서 광고가 공고 대신 단독으로 표시되지 않도록 처리합니다.
- 첫 방문 웰컴 팝업에 실제 AdFit 광고를 호출하지 않습니다.

## 3. 광고단위와 호출 관리

광고단위 ID와 지원 크기는 [`public/adfit-config.js`](../public/adfit-config.js)를 기준으로 확인합니다. 예시 ID나 타 서비스의 ID를 넣지 않습니다. 발급된 ID는 브라우저에 전달하는 공개 광고 식별자이므로 API 인증키나 비밀정보로 취급하지 않습니다.

| 조건 | 처리 |
| --- | --- |
| 설정 비활성 | 실제 광고 요청 없음 |
| `allowedHosts`에 없는 호스트 | 실제 광고 요청 없음 |
| ID 미발급 또는 사용 가능한 규격 없음 | 해당 지면을 요청하지 않음 |
| `?adPreview=1` | 명시적인 광고 미리보기 UI만 표시, AdFit 스크립트·광고 요청 없음 |
| 등록된 운영 도메인과 발급된 ID | AdFit 연결, 심사 상태와 광고 재고에 따라 송출 여부가 달라질 수 있음 |

외부 SDK는 중복 로드하지 않습니다. 목록 검색이나 화면 갱신 시 기존 광고 DOM을 관리해 같은 단위를 여러 활성 영역에 만들지 않습니다. 검색·페이지 이동·접기·펼치기마다 강제로 새 광고를 요청하거나 앱의 주기 타이머로 광고를 갱신하지 않습니다.

`data-ad-onfail` 등 SDK 응답과 스크립트 로드 오류에 따라 해당 지면의 빈 공간을 정리합니다. 광고가 보이지 않는다는 이유로 반복 재시도하지 않으며, 임의의 짧은 대기시간만으로 정상 로딩 중인 광고를 제거하지 않습니다.

하단 광고의 **최초 요청 중** 사용자가 접거나 입력·모달 때문에 숨겨진 상태에서 실패한 경우에만, 복귀 후 접힌 ‘광고 펼치기’ 바를 유지합니다. 사용자가 직접 펼치기를 누르면 **최대 1회** 복구하며, 다시 실패하면 지면을 숨깁니다. 자동으로 재시도하지 않습니다. 일반 미송출, 정상 송출 이후 실패, 목록 광고 실패, SDK 다운로드 실패에는 이 복구를 적용하지 않습니다.

## 4. AdFit 매체 등록·심사

1. AdFit 관리 화면에서 **지원한눈 / Web / `policyfundfinder.designboard.net`** 매체를 확인합니다.
2. 하단 모바일 320×50, 하단 PC 728×90, 목록 320×100의 전용 광고단위를 발급합니다.
3. 관리 화면에서 확인한 ID와 규격을 설정 원본에 연결하고 Pages로 배포합니다.
4. 운영 URL에서 실제 광고 호출을 확인합니다. AdFit 매체 심사는 광고단위 생성·설치 후 광고 호출이 발생해야 진행됩니다.
5. 관리 화면의 심사 상태와 실제 송출을 별도로 확인합니다.

| 확인 대상 | 확인 근거 |
| --- | --- |
| 코드 반영 | 해당 커밋의 Pages 배포 성공과 운영 파일 내용 |
| SDK·광고 호출 | 운영 화면의 발급 ID, SDK 로드, 광고 응답 |
| 매체 심사 | AdFit 관리 화면의 매체 상태 |
| 실제 광고 송출 | 운영 화면에 반환된 실제 배너 |

코드를 배포했다고 매체 승인을 완료한 것으로 표시하지 않습니다. 심사 대기·광고 재고 없음·브라우저 차단 등 미송출 상태도 코드 오류와 구분합니다.

## 5. 개인정보 안내

Kakao AdFit은 광고 제공·측정과 부정 이용 방지 과정에서 IP 주소, 브라우저·기기 정보, 쿠키 등 온라인 식별정보, 광고 요청·노출·클릭 정보를 카카오 정책에 따라 처리할 수 있습니다. 지원한눈은 브라우저에 저장한 사업 프로필·관심사업·준비 메모를 광고 요청 필드에 넣지 않습니다. 앱이 입력자료를 직접 전달하지 않는 것과 외부 광고 스크립트가 접속·광고 관련 정보를 처리하는 것은 구분해 안내합니다.

개인정보처리방침은 [`public/privacy.html`](../public/privacy.html)과 Google Play용 공개 페이지 및 기존 경로를 함께 유지합니다. 광고 도입 후에도 광고가 없다고 안내하는 문구를 남기지 않습니다. 접기 버튼은 광고의 화면 표시를 조절하며, 이미 처리된 광고 측정 기록을 삭제하거나 카카오의 광고 설정을 변경하는 기능은 아닙니다.

Google Play Console에서 광고 포함 여부·데이터 보안 항목이 실제 앱 동작과 일치하는지 확인해야 합니다. 저장소의 개인정보 HTML 수정은 Console 설정을 자동 변경하지 않습니다.

## 6. 배포와 검증

기존 [`OPERATIONS.md`](../OPERATIONS.md)의 GitHub Actions 배포 절차를 사용합니다. 광고 코드만 바뀌면 최신 공고를 다시 수집할 필요 없이 기존 검증된 자료로 배포할 수 있습니다.

```sh
npm run test:pages
node scripts/build-pages.mjs
```

실제 광고를 클릭하거나 반복 노출을 유도해서 검증하지 않습니다. 반복 UI 검증은 [광고 미리보기](https://policyfundfinder.designboard.net/?adPreview=1)에서 진행합니다.

| 확인 항목 | 기대 결과 |
| --- | --- |
| 모바일 360·390px와 PC | 규격에 맞는 지면, 좌우 잘림 없음, 메뉴·본문·비교함 겹침 없음 |
| 접기 → 펼치기 → 새로고침 | 버튼 상태와 보관된 세션 선택 일치 |
| 상세 → 첨부파일 뷰어 → 닫기 | 하단 광고 임시 숨김, 상세 레이어·검색 위치 유지 |
| 검색 입력·필터·페이지 이동 | 검색 결과 정상 변경, 광고 DOM·SDK 중복 생성 없음 |
| 공고 0~6개와 7개 이상 | 0~6개에는 목록 광고 없음, 7개 이상에서 6번째 뒤 최대 1개 |
| 미허용 호스트·미리보기 | 실제 AdFit 요청 없음 |
| 광고 미송출·네트워크 오류 | 기능 사용 가능, 빈 공간 정리, 반복 재요청 없음 |
| 하단 최초 요청 중 숨김 상태에서 실패 | 복귀 후 접힌 바 유지, 직접 펼칠 때만 최대 1회 복구, 재실패 시 숨김 |
| 운영 배포 | `/data/manifest.json`과 광고 정적 파일 응답 정상, 공고 데이터 유지 |
