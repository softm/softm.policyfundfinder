# 지원한눈 · Policy Fund Finder

서비스: https://policyfundfinder.designboard.net
저장소: https://github.com/softm/softm.policyfundfinder

GitHub Actions가 공고를 수집·검증하고 GitHub Pages가 정적 사이트를 제공합니다. 검색·분야·중분류·지역 필터·맞춤 조건 비교는 브라우저의 Web Worker에서 실행합니다. 사업 프로필, 관심사업, 신청 준비 기록은 브라우저에 저장합니다. 상시 운영 API 서버나 DB가 필요하지 않습니다.

## 데이터와 갱신

- 기업마당 공식 API + Npay 공개 검색 목록의 과거 공고까지 전체 수집합니다.
- 제목·마감일 기준으로 중복을 통합하고 기업마당 상세를 우선합니다.
- 원천 전체 건수, 고유 ID 수, 페이지 번호, 최종 원천 건수와 배포 파일 해시를 검증합니다. 목록 수집 실패 시 이전 배포를 유지합니다.
- 검색 목록과 상세 32개 분할 파일은 gzip JSON입니다. 첫 화면은 검색용 목록과 해당 페이지 상세만 읽습니다. 최신 브라우저의 압축 해제 기능을 사용합니다.
- 진행중 상세를 수집하고 과거 상세는 마지막 성공 자료를 유지합니다. 상세가 미수집된 공고는 목록 정보와 공식 원문 링크를 제공합니다.
- 첨부파일 원본 링크를 유지합니다. 저장·검증된 PDF만 내장 뷰어를 표시합니다. PDF 수집은 회당 요청 수와 파일·전체 용량을 제한합니다.
- 매일 06:17 KST 예약, 소스 푸시 때 기존 완전한 자료로 배포, Actions의 수동 실행 때 최신 수집을 선택할 수 있습니다.

## 개발·검증

Node.js 22 이상이 필요합니다. Pages 경로는 외부 패키지 설치 없이 실행합니다.

```sh
node --test --test-concurrency=1 tests/core.test.mjs tests/catalog.test.mjs tests/pages.test.mjs
node scripts/build-pages.mjs
# BIZINFO_API_KEY 환경변수가 있으면 기업마당도 갱신합니다.
node scripts/collect-pages.mjs
node scripts/build-pages.mjs
```

출력은 `_site/`입니다. 브라우저는 `/api/*`로 네트워크 요청하지 않습니다. 기존 UI 호출을 정적 데이터 어댑터가 처리합니다. `server/`, D1 마이그레이션과 Sites 설정은 기존 구현 보존용으로 남아 있으며 Pages 빌드에는 포함되지 않습니다.

배포·인증키·도메인 설정은 [OPERATIONS.md](OPERATIONS.md)를 확인하세요.


## 자동 지원방식 분류 (2026-10-16)

이전에는 네이버 공고가 전부 '지원사업'으로 남았지만, 현재는 원천 태그·제목·지원방식·상세 내용 순으로 지원금, 정책융자, 이자지원, 바우처, 서비스·현물, 금융지원, 복합지원과 미확인 지원사업을 보수적으로 분류합니다. 제목에 융자와 이차보전이 함께 등장하면 금융지원으로, 원천 태그에 보조금과 대출이 함께 등장하면 복합지원으로 표시합니다. 최종 자격이나 지급 성격을 확정하는 분류가 아닙니다. 상세 팝업에 자동 분류 근거를 표시하고 공식 원문을 연결합니다. 원천 분야·중복 통합 규칙·공고 ID는 유지합니다.

새로 수집하는 데이터뿐 아니라 이전 성공 수집본도 배포 시 재분류합니다. 진행 중 상세 미수집 건수와 지원 유형별 건수를 data/manifest.json 상태값에 추가합니다. 기업마당 API 키가 없으면 이전 자료로 운영하며 API 키를 저장소 Secrets.BIZINFO_API_KEY에 설정해야 자동 갱신됩니다. 검증: `npm run test:pages` 및 Actions Pages 빌드.


## 공고 상세 줄바꿈·항목 레이아웃 (2026-10-16)

네이버 상세 JSON이 실제 개행·HTML 없이 NBSP와 `ㅇ 지원내용`, `- 항목`, `* 주의사항`, `ㅇ 지원금액` 등으로 연결된 경우에도 브라우저의 `public/notice-text.js`가 공통적으로 문단·소제목·목록·주석으로 복원합니다. 과거에 수집해 공백으로 합쳐진 공고도 화면 표시 시 복원하므로 전체 재수집 없이 반영됩니다. 새로 수집하는 네이버 공고는 개행을 보존하는 `normalizeNoticeText`로 상세 필드를 저장합니다. 상세 상단에는 지원 금액 한 줄만 축약하고, 상세 본문에는 지원 조건 전문을 표시합니다. HTML 특수문자는 이스케이프하며 원문의 지원 조건과 금액을 임의 수정하지 않습니다. 회귀 테스트: `tests/notice-text.test.mjs`.
